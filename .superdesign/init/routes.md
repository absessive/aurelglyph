# Routes and entry surfaces

## React Vite example

Entry: `examples/react-vite/index.html` → `src/main.tsx` → `src/App.tsx`. React 19 + Vite 6; no React Router or file-based routes. The one App file owns hash selection, shared rail, theme switcher, and all four page functions. Native shell examples inside ComponentsPage are specimens, not additional app routes.

| URL | Page function / source | Layout | Content |
| --- | --- | --- | --- |
| / or /#overview | OverviewPage, examples/react-vite/src/App.tsx | example-shell rail + workbench | Package hero, button/field examples, consumer setup |
| /#components | ComponentsPage, same file | same | Interaction, form, layout, mobile-shell, navigation, data, disclosure, and icon specimens |
| /#usage | UsagePage, same file | same | React/CSS/Rails/Swift install and theme code blocks |
| /#changelog | ChangelogPage, same file | same | Version and release summary |

Full route definitions and hash-state logic from the App source (there is no standalone router config):

```tsx
const navItems = [
  { id: "overview", label: "Overview" },
  { id: "components", label: "Components" },
  { id: "usage", label: "Usage" },
  { id: "changelog", label: "Changelog" }
] as const;
  const [activePage, setActivePage] = useState<PageId>(() => {
    const hash = window.location.hash.replace("#", "");
    return navItems.some((item) => item.id === hash) ? (hash as PageId) : "overview";
  });
  useEffect(() => {
    const handleHashChange = () => {
      const hash = window.location.hash.replace("#", "");
      if (navItems.some((item) => item.id === hash)) {
        setActivePage(hash as PageId);
      }
    };

    window.addEventListener("hashchange", handleHashChange);
    return () => window.removeEventListener("hashchange", handleHashChange);
  }, []);
        {activePage === "overview" && <OverviewPage appearance={appearance} mode={mode} theme={theme} />}
        {activePage === "components" && <ComponentsPage />}
        {activePage === "usage" && <UsagePage appearance={appearance} mode={mode} theme={theme} />}
        {activePage === "changelog" && <ChangelogPage />}
```

## Generated public documentation

Generated by `scripts/pages.ts`; edit the generator, not generated HTML. Outputs: `docs/index.html` (Overview), `docs/components.html` (component specimens + executable support manifest), `docs/usage.html` (adapter usage), and `docs/changelog.html`. Each uses generator `pageShell` with common brand/header/navigation/theme controls, default quiet/light/royal-purple. Published domain comes from `docs/CNAME`: `aurelglyph.absessive.com`. Link paths are real .html pages, not hash navigation.

## Static instrument preview

`preview/index.html` is a standalone single-file HTML/CSS/JS specimen. It has a Workbench/Notes/Systems/Lab/Archive/Settings rail, but all navigation links target `/`; they are not implemented app routes. This is a separate warm instrument preview, not the generated documentation source.

## React Native native host

`examples/react-native-smoke/index.js` registers App from `App.tsx` with the app.json name `AurelglyphSmoke`. Native iOS AppDelegate and Android MainActivity/MainApplication launch that module. No native router: SafeAreaProvider → ThemedSmokeHost → AurelglyphProvider → theme controls + SmokeWorkbench. A consumer-owned native Modal nests a second AurelglyphOverlayHost. Overlay, selection, menu, and command-palette controls are local state, not route navigation. Metro watches the workspace; adapter package is `@aurelglyph/react-native`.

## SwiftUI native host

`examples/swiftui-smoke/App/AurelglyphSwiftUISmokeApp.swift`: @main App → WindowGroup → NativeWorkbench → AurelglyphAppShell. Theme/release/form cards and a dialog are state-controlled; no URL router. Xcode app references root SwiftPM `AurelglyphUI` module, whose sources live at `packages/swift/Sources/AurelglyphUI`. Root and package-local Package.swift select the same module and font resources.
